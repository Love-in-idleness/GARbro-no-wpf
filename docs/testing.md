# Portable build and tests

Install a .NET 10 SDK, then run from the repository root:

```sh
dotnet build GARbro.NoWpf.slnx -c Release
dotnet test GARbro.NoWpf.slnx -c Release --no-build
python3 tools/inventory-formats.py --check
```

The historical `GARbro.sln` still targets .NET Framework 4.7.2 on Windows.
Its workflow exports the actual MEF catalog with `tools/export-legacy-catalog.ps1`.
The versioned source inventory records exports from explicit legacy project items;
it is not a substitute for the runtime catalog or successful extraction tests.

Regenerate synthetic fixtures with `python3 tools/generate-fixtures.py`.
They are independent Python encodings of format layouts, not game assets.
`tools/test-legacy-fixtures.ps1` compares the historical Windows decoders with the
same entry/hash manifest used by the portable integration tests.

In restricted build environments, MSBuild can run without compiler servers:

```sh
dotnet test GARbro.NoWpf.slnx -c Release -m:1 -nr:false -p:UseSharedCompilation=false
```

This is a build invocation option, not a repository-specific local path dependency.

Pixel vectors are generated by `tools/generate-pixel-vectors.py`. Portable tests
compare every supported source pixel kind with those vectors; the Windows legacy
workflow independently creates WPF bitmaps and compares their BGRA output using
`tools/test-wpf-pixels.ps1`. This detects packed-pixel and alpha rounding changes.

Preview packaging is reproducible from source with:

```sh
python3 tools/package-release.py --rid linux-x64
python3 tools/smoke-package.py --rid linux-x64
```

Supported RIDs also include linux-arm64, win-x64, win-arm64, osx-x64 and osx-arm64.
CI builds Linux x64, Windows x64 and macOS arm64 archives. macOS packaging includes
an app bundle; packages are unsigned and require the .NET 10 runtime. Core code,
codec native assets, license texts and a dependency manifest are included.

CI unpacks each preview archive into a fresh temporary directory and exercises the
published CLI, native raster conversion, safe extraction and bundled v148 scheme
imports. It also checks that the desktop bundle contains the same scheme data and
that compatibility ledgers, licenses and dependency records survive packaging.

Gray16 conversion uses a frozen threshold table observed from the original Windows
WPF conversion. Both portable and Windows reference tests check all 65,536 values,
including every quantization boundary. The table's source commit, workflow run and
job are recorded in `tests/fixtures/generated/gray16-quantization.json`.

Additional synthetic fixtures cover ZIP and Majiro v1/v2/v3. Audio fixtures are
encodings of the generated 440 Hz WAV, produced with FFmpeg by
`python3 tools/generate-fixtures.py --audio`. Tests verify decoded length and
signal energy, AIFF PCM retention, WAV conversion, and one-byte MP3 reads/seeks.

The release helper has separate tests: `python3 -m unittest discover -s tools/tests`.
See [publishing a release](releasing.md) for release tags, notes and package checksums.

The portable catalog now includes the historical Legacy assembly. Synthetic DL1,
PAK/ALPHA and PAK/ASURA archives verify listing and raw/LZSS extraction by path,
size and SHA-256 against both runtimes. `legacy555.mbp` checks BGR555 image pixels
and metadata. RCT writer/reader round trips and bounded, immutable region replacement
cover the newly adapted image paths. Bundled schema-2 data imports all 77 consumed
v148 scheme groups; package smoke tests compare their manifest and content digest.

Embedded-raster tests distinguish opaque RGB, direct RGBA and indexed PNG data.
This matters for PNG/ISM, whose alpha inversion applies only to direct BGRA images.
The historical Windows workflow verifies the same PNG colors/types and linear
color-subtraction vectors against WPF. AGF literal pixels and obfuscated BBM
bitmap fixtures also pass through the portable and historical image decoders.

Composite-path fixtures cover PMS alpha, DPNG tile placement, opaque CWP output
and HZC multi-frame extraction. Canvas tests exercise source crops, destination
offsets, pointer bounds, ownership, freezing and clipped source-over composition.
Windows also renders a source-over vector through WPF. The NekoNyan strip fixture
uses a synthetic lossless WebP slice; regenerate its encoded input with
`python3 tools/generate-fixtures.py --webp` (requires FFmpeg with libwebp).
This strip fixture is portable-only; the legacy comparison does not load the
external Windows WebP codec.

`tools/fixture_nrbf.py` writes minimal NRBF records directly from the published
record layout. GX4Lib and Unity fixture indexes are independent of both CLR
serializers. The portable decoder never enables BinaryFormatter; the legacy
Windows comparison verifies the same archives through the original binders.
Negative fixtures cover unrecognized root types and excessive array lengths.

Experimental fixtures add RGSSAD v1/v3, UTF-16 IRIS directories, IPT tiles and
JSON ATX atlases to the shared Windows/portable comparisons. Portable-only tests
exercise WebP, Opus signal energy, and RPG Maker resources from two game roots
with different synthetic keys. `--audio` also regenerates the Opus tone.
`tools/fixture_pe.py` creates PE32/PE32+ resource tables without machine code;
`tools/test-pe-resources.ps1` checks the original Win32 resource/version accessors
against the same names, data and fixed versions used by managed tests.

`tools/fixture_cabinet.py` creates CAB headers, reserved fields, checksums and
stored/MSZIP blocks independently. Python zlib encodes each raw block; the encoder
also asserts that later MSZIP blocks cannot decode without their dictionary.
These archives join the shared hash comparisons. Portable negative tests corrupt
checksums and exercise the explicit unsupported-LZX path. Hibiki has a separate
portable synthetic key/index fixture; it is not part of the Windows corpus.

`tools/fixture_igs.py` uses Python SQLite, independent per-page SHA1/RC4 encryption
and OpenSSL AES-CBC to create IGS archives. Regeneration requires the OpenSSL CLI;
ordinary build/test runs use the checked-in files. The `portable_archives` manifest
section also runs through the extraction/hash tests but is excluded from the
historical SEE-dependent comparison. IGS tests include read-only literal paths,
PKCS7 failures, invalid archive placements and active-journal rejection.

The Side-B fixture uses independent `py3rijndael==0.3.3` encryption with 256-bit
blocks, CBC and zero padding, plus Python zlib. Regenerate it with
`python3 tools/generate-fixtures.py --crypto` after installing that generator-only
dependency; ordinary regeneration retains the checked-in encrypted fixture.
The shared manifest compares extracted paths, sizes and hashes against .NET
Framework's original Rijndael implementation as well as the modern backend.

Main-provider fixed-size headers, literals and pixel planes also fill across
short reads. The DRG fixture verifies known pixels on a one-byte-at-a-time stream
and rejects truncation. GUI lifecycle tests ensure invalid JSON options restore
the open button and closing during asynchronous opening disposes the result.

`tests/GARbro.Desktop.NativeSmoke` uses the actual Avalonia platform backend and
window, opens the XFL fixture, captures its rendered content and extracts files.
Run `python3 tools/smoke-desktop.py` after building; Linux needs a display (or
`xvfb-run -a`). CI runs this on each desktop platform and retains a PNG alongside
test results. This does not exercise native file-picker dialogs or audio devices.

`python3 tools/check-public-corpus.py` downloads the official RenPy 8.5.3 SDK ZIP,
checks its pinned SHA-256 against the published release digest, extracts it with
the CLI and compares all 3,222 files (356,359,448 uncompressed bytes) against
Python's independent ZIP reader. CI retains a JSON report for each platform.
This is a real released software package, not an engine-specific RPA game archive;
its scope is ZIP extraction. The SDK assets are downloaded for testing only and
are not included in GARbro's repository or packages. Source and checksum URLs:
[release](https://www.renpy.org/release/8.5.3),
[checksums](https://www.renpy.org/dl/8.5.3/checksums.txt).

Worker tests run real child processes that stall or allocate/touch memory. They
verify timeout, resident-memory termination, cancellation, cleanup of owned
pending files and preservation of existing files. A separate worker integration
test exits a real parent process without awaiting cleanup, checking that its
worker is terminated and pending outputs are removed. Another integration
test lists, previews and extracts; changing the archive invalidates its metadata.
Another integration test removes `PATH`, `DOTNET_ROOT` and `DOTNET_HOST_PATH`
and opens an archive through the worker, covering host discovery when a system
desktop launcher does not inherit a shell's environment.
Desktop tests cover cancelling opening, closing mid-open and filtering every
row away and back. Published-package checks also start the shipped worker host.

The CLI defaults to a supervised command with `--timeout 300` and
`--max-memory 1073741824`; the desktop exposes seconds/MiB in Settings.
Memory sampling can overshoot between checks and is not a security sandbox.
Filesystem recursion has a depth limit; archives inside archives are not
automatically extracted during loading. Explicit Recursive extraction / CLI --nested handles child archives with a shared budget.

Linux additionally runs `tools/smoke-wayland.py` in a private headless compositor.
It verifies the native Wayland default with no X display, actual text-input-v3
composition/commit, UTF-8 surrounding deletion and focus transfer. See
[Linux desktop](linux-desktop.md) for dependencies and the focus-state adapter.


## Desktop v0.2 and installers

`ResourceBrowserTests` exercises lazy directory/nested browsing, unknown-extension
child archives, quotas shared across nesting/retries, session parameter retry,
parent-owned PCM audio artifacts, actual NScripter decoding and all 22 declared
archive writers creating and reopening a synthetic archive. `SettingsTests` covers
JSON persistence/corruption, localization resources, diagnostic redaction, numeric
SemVer ordering and SDL Play/Pause/Seek/Stop with the dummy driver. Run tests with
`SDL_AUDIODRIVER=dummy` on CI; real audio-device acceptance remains separate.

Build Linux DEB with `python tools/package-release.py --rid linux-x64 --installer`.
`python tools/smoke-deb.py artifacts/garbro-0.2.0-preview.1-linux-x64.deb` installs
that actual package into disposable Debian 13 and Ubuntu 24.04 containers with an
external .NET 10 runtime, lists/extracts a fixture, activates the desktop file in
Xvfb and uninstalls. This does not substitute for native portal/Wayland testing.
The Windows packager uses Windows SDK MakeAppx and SignTool, generates a disposable
self-signed certificate, signs, verifies and discards the private key. The MSIX
smoke installs a lower same-identity version, upgrades, activates a file using
IApplicationActivationManager and removes the package/test trust.

Python installer tests enforce version ordering and exclude common/media/executable
extensions from associations. Release preparation requires the three archives,
DEB, signed MSIX, public certificate and database assets before generating SHA-256.
